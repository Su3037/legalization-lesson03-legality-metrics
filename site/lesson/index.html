1. 行、站点、坐标、区间

本课的芯片宽 12、高 6，分成三行，每行高 2，行的底边在 y = 0、2、4。每一行又切成宽 1 的站点。单元的坐标指它的左下角。所以 A 在 (4, 2)，意思是它从第 4 格开始，占住 4 到 6 这一段。我们把这一段写成左闭右开的区间 [4, 6)：4 算在里面，6 不算。

行（háng） 单元可以落脚的水平带。站点 行里宽 1 的格子。锚点 单元左下角。区间 [x, x + w)，单元在行里占的长度。

2. 五条规则

一张布局合法，当且仅当下面五条同时成立（并且输入完整，见第 3 节）。

规则一：在行上

单元的底边必须正好落在某一行的底边上。

规则二：对齐站点

单元的左边必须对齐某个站点：x 减去第一个站点的位置，是站点宽的整数倍。差半格也不行。

规则三：整个单元在芯片内

要看整个矩形，不只是左下角那个点：x ≥ 0，x + w ≤ W，y ≥ 0，y + h ≤ H。

规则四：同一行不重叠，相接可以

同一行的两个单元，区间 [a.x, a.x + a.w) 和 [b.x, b.x + b.w) 不能相交，也就是不能同时满足 a.x < b.x + b.w 和 b.x < a.x + a.w。两个单元只是碰在一起（a.x + a.w = b.x）时没有共用任何长度，合法。

规则五：固定单元不能动

如果 D 被声明为固定单元，它就必须待在声明的位置 (8, 4)。挪到空地上也算违规。关掉固定约束，问题变了，答案也可能跟着变。实验台上有“固定约束”开关，可以亲手对比。

3. 检查器：第一条错误和全部错误

把五条规则合在一起，就是一个完整的检查器。它先确认输入是完整的：少了单元、多了没声明的单元、坐标不是有限的数、线网或固定声明里出现了没声明的单元，都直接判为输入无效，不再做几何检查，也不会替未知单元编一个默认宽度。然后它逐个单元、逐对单元地检查，把每一条违规都记下来。

  1. 输入：芯片、单元、线网、固定声明；布局；参考布局
  2. 若输入不完整或有非法数值 → 输入无效，停止
  3. 对每个单元 c：
  4.   若 c.y 不是任何一行的底边 → 记 ROW
  5.   若 (c.x − x0) 不是站点宽的整数倍 → 记 SITE
  6.   若 c 的整个矩形不在芯片内 → 记 BOUNDS
  7.   若 c 是固定单元且坐标变了 → 记 FIXED
  8. 对同一行里的每一对单元 (a, b)：
  9.   若 [a.x, a.x+a.w) 与 [b.x, b.x+b.w) 相交 → 记 OVERLAP
  10. 合法 ⇔ 一条记录都没有；第一条记录 = 最先发现的错误
  11. 位移 = Σ |x−x参考| + |y−y参考|；HPWL = Σ 线网中心包围盒的宽 + 高

回到开场的布局：第一条错误是 A 和 B 重叠，但完整的清单有三条（A/B、A/C、B/C）。只报第一条的检查器会让人修了一处又冒出一处；本课的检查器两样都给。实验台的“逐步检查”会一行一行高亮上面的伪代码。

坐标为什么在内部换成整数

检查器把所有坐标乘以 1000（数据库单位，DBU）再比较，只有离整数不到 10−6 时才取整。这样站点宽是 0.19 之类的非整数时，“对齐站点”也能精确判断，不会因为浮点误差把 0.57 判成没对齐。真实设计里 DEF 文件本来就是整数 DBU（gcd 用 2000 DBU/µm）。

4. 取整不等于合法

有人会说：把坐标四舍五入，不就合法了吗？全局布局给的是小数，取整以后每个单元都对齐了站点，也都落在行上。可是 A 和 B 还是叠在一起。取整只解决了对齐，没有解决重叠。

5. 两个指标：位移和半周长线长

位移：从一个不变的参考算起

每个单元算它离参考位置的横向距离加纵向距离 |Δx| + |Δy|，再把所有单元加起来。检查器同时报告总和、平均值和最大值。参考位置要先说清楚，而且中途不能换：如果每挪一次就把参考换成当前布局，第二次挪动就会把第一次的账抹掉。实验台上的参考布局只有在你明确点“设为新参考”时才会改变。

半周长线长（HPWL）：用单元中心

一个线网连着几个单元。取每个单元的中心，框出一个最小的矩形，宽加高就是这个线网的半周长线长；所有线网加起来就是总 HPWL。用中心而不是左下角，宽度不同的单元才算得公平。只连一个单元的线网，HPWL 为 0。

位移 单元离参考位置的 |Δx| + |Δy|。参考布局 计算位移的起点，事先声明，中途不变。半周长线长（HPWL） 线网中心包围盒的宽 + 高。DBU 数据库单位，内部比较用的整数坐标。
指标只是诊断。不合法的布局也会算出位移和 HPWL，但会标明“不合法”；分数再好，也不能把不合法变成合法。

6. 会改变数字的约定

同一张布局，换一个约定，数字就会变。比较两篇论文或两个工具的数字之前，先对齐这些约定。

7. 修复演示与精确最优

现在来修开场那张布局。第一种办法，把这一行里的单元依次往右推：B 挪到 6，C 挪到 8，位移一共 6，HPWL 32。第二种办法，把 B 和 C 分别挪到上下两行：位移只有 4，HPWL 却变成 38。两个都合法。位移更小的那个，线长反而更长：说“更好”之前，要先说清楚比的是哪个指标。

那 4 是不是最少的？我们用精确求解器（OR-Tools CP-SAT）在同样的规则下求最少总位移：

所以在开场布局上，最少就是 4，而且有 48 种不同的摆法都能做到 4：练习里正确答案不止一个，挑战也按“是否合法、位移是否达到目标”判分，而不是和某一张标准答案比对。换成从小数出发的布局，启发式方法就会比最优多挪一些。表里的 Abacus 是 Spindler 等人 2008 年方法的一个小而忠实的实现（按行聚类、二次代价、固定单元把行切成子行），Abacus-lite 是教师材料里的简化版本。

8. 总和与最大值

位移的总和也不是唯一的说法。看这一行：X 掉在了 A 上面。让 X 一步跳到右边，总共挪 4，可是 X 一个人就挪了 4。让四个小单元各让 2 格，总共挪 8，但每个单元最多只挪 2。

精确求解器给出：这一行的最少总位移是 4，这时最大位移是 4；最大位移最少可以压到 2，这时总位移至少是 6。两者不能同时达到。所以有的比赛和工具会同时看平均值和最大值。例如 ICCAD 2017 合法化比赛除了平均位移，还对最大位移设了限制（这条来自文献记忆，比赛网站在本环境无法访问，见来源核查）。

9. 真实检查器还查什么

这个检查器很小。真正的签核工具要查的更多，本课都没有检查：

  • 朝向：单元的朝向（N、FS 等）要和所在行的朝向对上，电源轨才能接得上。
  • 限定区域与禁止放置区（region / fence、blockage）：某些单元只能放在指定区域，有的区域什么都不能放。
  • 单元之间的最小间距与边缘类型规则（edge spacing）。
  • 跨好几行的高单元（多行高单元）：要检查电源轨对齐和每一行的重叠。
  • 填充与布线资源：比如引脚是否可达、填充单元能否插入。

我们在 OpenROAD 自带的 gcd 小设计（Nangate45，461 个单元，57 行）上试过：

布局本课检查器OpenROAD check_placement是否一致

在两边都检查的规则上，OpenROAD 和我们的检查器结果对得上。我们用的 OpenROAD 版本（2.0-12381）的 check_placement 不检查朝向，这一点由变异测试 M16 确认。全局到详细布局的位移：347 个单元，总和 253.3 µm，平均 0.73 µm，最大 2.43 µm。

11. 背景与参考资料

用在哪里：每个合法化算法（Tetris、Abacus、基于网络流或整数规划的方法）的结果，都要先过一遍这样的检查器；OpenROAD 在详细布局之后运行 check_placement，DREAMPlace 在合法化之后运行 legality_check。比赛用检查器给参赛结果判“合法/不合法”，再用位移或线长打分。
